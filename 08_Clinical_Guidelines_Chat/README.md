# Clinical guidelines chat (Eswatini)

Retrieval-augmented chat over ten Eswatini national guideline documents (HIV 2022 and its 2024 Amendment, PrEP 2025,
Linkages SOP, TB 2025, NCDs/Injuries/Mental Health, Mental Health Desk Guide, ANC, Family Planning 2021, STI and
Viral Hepatitis 2026 draft). The app itself (`guideline_chat/app.py`, `chat.py`) lives outside this repo; this folder
holds the chunked guideline text, the benchmark, the reviews and the notes on improving the app.

**Start here:** `NEXT_STEPS.md` (current state and what to do next).

| Path | What it is |
|---|---|
| `NEXT_STEPS.md` | Checklist: changes to apply, test questions, longer-term work. |
| `APP_REVIEW_NOTES.md` | App review: settings, bugs, test results on llama3.1:8b and qwen2.5:14b, model swapping fix, roadmap. |
| `app_review/` | Draft system prompt (v2), suggested `app.py` / `.env` changes with code, note for a colleague. |
| `chunks_v3/` | **The chunk set to index** (`chunks.jsonl`). README describes fields and the quality sweep. |
| `chunks_v2/` | Earlier cleaned set; superseded for indexing but needed to rebuild `chunks_v3`. |
| `table_reextract/` | Pipeline that re-extracted every table, box and flowchart from the PDF page images and builds `chunks_v3`; per-guideline review pages. |
| `chunk_validation/` | 50-item validation sample of `chunks_v3` with review notes. |
| `benchmark_review/` | The 188-question benchmark (152 revised + 36 added) and the review page clinicians use to check reference answers (offline file, or hosted on a Google Sheet via Apps Script). |
| `sample_questions.jsonl` | The original 152 questions; input to `benchmark_review/build_review_data.py`. |
| `SOURCE_ISSUES.md` | 680 errors and inconsistencies found in the guidelines themselves (generated by `table_reextract/make_source_issues.py`). |
| `source_issues_review/` | Those issues sorted into review tiers (`PRIORITY_REVIEW.md`, `source_issues_tiered.csv`). |
| `rag_eval_k8/` | Baseline evaluation of the first version of the chat (k=8, old chunks): 34% of answers fully correct; also shows the Llama judge could not tell good answers from bad. |
| `eval_process/` | Slide deck describing the evaluation process. |
